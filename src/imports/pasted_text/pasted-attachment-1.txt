- Use a warm off-white background with deep charcoal text and premium dark

- Use a cinematic accent gradient from violet/purple to coral/orange.
- Use rounded cards with 16px to 20px corner radius.
- Use clean modern typography with large confident headings.
- Use generous whitespace and strong visual hierarchy.
- Use subtle hover animations, card elevation, smooth transitions, and skeleton 
  loading states.
- Ensure good contrast, readable text, visible focus states, and keyboard 
  accessibility.
- Do not use fake broken image icons. Always show a graceful poster placeholder

MOVIE POSTER DATA INTEGRATION

Prepare the design and data layer to use TMDB API for accurate movie posters, 
backdrops, titles, genres, ratings, cast, runtime, and synopsis.

Use the following integration behavior:

- Search movies using TMDB search results.
- Retrieve movie details using the selected TMDB movie ID.
- Retrieve poster and backdrop paths from TMDB.
- Build poster URLs from the TMDB image base URL and returned poster path.
- Never construct image URLs from a movie title.
- Store the TMDB movie ID with every movie card.
- Use the selected movie ID when opening the movie detail page.
- Use a local fallback dataset if the API key is unavailable.
- Use local placeholder posters only when the API returns no image.
- Add a small attribution item in the footer or About/Credits area:
  "This product uses the TMDB API but is not endorsed or certified by TMDB."

Use these conceptual data fields:

{
  id,
  tmdbId,
  title,
  originalTitle,
  posterUrl,
  backdropUrl,
  overview,
  releaseDate,
  runtime,
  genres,
  language,
  certificate,
  rating,
  voteCount,
  cast,
  showtimes
}

Do not hardcode poster URLs into individual components. Centralize movie 
data in a movies service or API layer so the frontend can later connect to 
a real backend.

If live API connectivity cannot be implemented inside the prototype, create 
a clean mock service with the same interface:

- searchMovies(query)
- getMovieDetails(tmdbId)
- getTrendingMovies()
- getRecommendedMovies(preferences)
- getMovieShowtimes(tmdbId, date, city)

Use realistic fallback poster URLs or placeholder assets in the mock data, but 
keep the API integration boundary clearly separated.
